## Intent

**Problem:** A run in flight cannot be stopped: `run.stop` is a type in `src/shared/commands.ts` with no channel, preload method, handler or control. A stopped turn would read as a failure (`run:failed` plus a `turn failed` line), a stop that is not acknowledged has no fallback, and after an app relaunch the transcript holds no card at all, so Story 2.7's dead-card clause and Story 2.11's orphan card and stop clauses (FR6, FR83–FR86, FR100) have never been able to fail.

**Approach:** `run.stop(runId)` writes one in-band interrupt line to that run's session and marks the run as stopping. The turn's own `result` row ends it as `run:stopped`; the session stays open. An interrupt not acknowledged ends the session and says so in the harness's own register. One plain `stop` button sits on the full card head and on the collapsed line. Run cards are stored with the transcript, so a relaunch shows each as a dead terminal card.

## Boundaries & Constraints

**Always:**
- The interrupt is exactly `{"type":"control_request","request_id":"<id>","request":{"subtype":"interrupt"}}` plus `\n`, written once per stop request to the session of the run found by `runId` among the window's sessions, never through the roster and never `SIGINT`. Frame knowledge (`control_request`, `control_response`) stays in `session-process.ts`; nothing else names them.
- The run is marked `stopping` before the line is written. The terminal event is raised on the turn's `result` row and never on the `control_response`: a main-thread `result` with `is_error: true` on a stopping run is `run:stopped` (not `run:failed`), with no `turn failed` line and no `turn:failed` persona event; a `result` without `is_error` on a stopping run is `run:finished`. There is no "stopping…" state, no event and no change on the card between the press and the `result`.
- Acknowledged means a `control_response` carrying the request's id with `subtype: "success"`. The fallback runs when that id gets another subtype, the write fails, the process closes first, or nothing answers within `STOP_ACK_MS` (3000, on the injected `schedule`), and the run is still in flight: the session's process group is killed, the card ends with `run:stopped`, one harness line is written to the transcript (`harness:said`, never a persona's), and the session is closed (`session:closed`, reason `closed`). Exactly one terminal run event per run.
- An acknowledged stop never closes, kills or discards a session and writes no line to the transcript. A second `run.stop` for a run already stopping resolves ok and writes no second line. A `run.stop` for a run not in flight (ended, unknown, another window's) resolves `{ ok:false, error:{ code:'run/not-found', message:'run · no such run is in flight' } }`; the renderer swallows that code and says nothing.
- Stopping never touches the project's files: main has no path that reverts, patches, restores or deletes one, and no control, line or message offers to. No confirmation dialog, no cost copy on the control, no spinner, tooltip, badge, toast or sound.
- One native `<button type="button">` reading `stop`, drawn only while its card's run is `running` and an `onStop` was handed down, never disabled: on the full head after the elapsed time, on the collapsed line as a sibling of the expanding button after it (a button inside a button is invalid). It is its own tab stop under the shared `focus.css` ring (no `outline` or `:focus` in component CSS), takes no focus when drawn or removed, announces nothing (the lifecycle line already does), and is the same control in the thread, pinned and orphaned. Its accessible name is `stop · <name>` on the line (the persona's name) and `stop · <path>` on the card when a path is held, else just `stop`. Every value comes from `src/renderer/design/tokens.css`; its text uses `--dim`, not the faint tier (the faint-tier registry in `tests/negative-surface.test.ts` then needs no entry).
- The roster never decides a stop: an orphan's run (Story 2.11) shows the control on its collapsed line, and on its expanded card, and a stop on it halts the turn exactly as for a rostered persona; the orphan's header and `close session` stay and a stop never closes it. `close session` on an orphan with a run in flight ends it through the existing path (`run:failed`, `run/session-ended`, before `session:closed`); the card and transcript stay. An agent returning resumes the same session and card under the ordinary rule. A roster change mid-run changes no run, card or stop control.
- Run cards are stored with the transcript (`TranscriptFile.runs?`, `{ card, lastAt }[]`, `version` stays 1, older files without it load as none): each run's `RunCardSnapshot` is recorded after every run event (the transcript's debounced write and quit flush carry it) with the `at` of that event. On load a stored card whose status is `running` becomes `failed` with `error: { code:'run/session-ended', message:'run · the session ended' }` and `endedAt: lastAt`; any other keeps its terminal status. `conversation:get` returns the stored (earlier) cards first, then this launch's, as `runs`; sessions, busy and personas are never stored, so after a relaunch every persona reads idle, nothing is offered to resume, and the renderer draws the cards through its existing hydrated-terminal path: no ticking elapsed, no stop. `conversation.end` clears stored runs with the entries. A stored run that is not a run card is dropped and counted with the dropped entries (`persist/entries-dropped`).
- The harness line for a stop not acknowledged is lower case, mono-register, `·`-separated, no terminal punctuation: `stop not acknowledged · the session ended with the run` (placeholder copy until `bmad-ux` writes it).

**Never:**
- No `SIGINT`, no second interrupt, no result timeout, no "stopping…" state, no new event or command beyond the declared `run.stop`, no change to `RunStatus`, `RunStopped`'s payload, `RunCardSnapshot`, the card folds' status set, or the rail's annotation (`stopped` on the row is Story 3.8's). No section-reached wording on a stopped card (3.8). No restore, revert, undo or resume control.
- No persistence of sessions, busy sets, persona states, queues or the install model. No stop logic in the renderer beyond calling `stopRun` and swallowing `run/not-found`.
- No `stop` string, `onStop` or `run.stop` in `transcript.tsx` beyond passing the prop; no button in `transcript.tsx`, `sysline.tsx` or the pinned slice of `app.tsx`.

**Acceptance Criteria:**
- Given a run in flight, then its full card head (beside the elapsed time) and its collapsed line each carry a `stop` button, its own tab stop, with the shared focus treatment, and activating it calls `run.stop(runId)`, which writes one interrupt line to that run's session and no `SIGINT`.
- Given the interrupt is acknowledged, then the card reaches `stopped` on the turn's `result` row, nothing changes before it, the session stays open, a next turn is accepted, no confirmation, cost copy or "stopping…" state exists, and the file on disk is as written.
- Given the interrupt is not acknowledged, then the session ends, a harness line (never a persona's) says so in the transcript, the card ends once as `stopped`, and no cost is hidden.
- Given an orphaned session's run, then its collapsed line and expanded card carry a working stop found by run id, a stop leaves the session and its header open, `close session` ends the run's card terminal with the transcript kept, an agent returning resumes the same card, and a roster change mid-run changes nothing.
- Given the application is relaunched with a run card in the transcript, then it renders dead (no ticking, no stop), every persona reads `idle`, and nothing is offered to resume.
- Given the full suite, lint, typecheck and build, then all pass.

## Design Notes

- **A stop is the user's, so the card reads `stopped`, including on the fallback.** The interrupted turn's `result` is `error_during_execution` with `is_error: true`, indistinguishable by `subtype` from a failure (`spike-stop-semantics.md`; the fixture shows `stop_reason: "tool_use"`, the spike `null`), so main holds `stopping` on the run, set before the write because the ack and the `result` can arrive in one chunk. General failure classification (`subtype`, section reached, the rail's `stopped`) stays Story 3.8's.
- **Dead is `failed` with the existing `run/session-ended` envelope.** A run cut off by the app quitting is exactly "the session ended with the run", so no status is added: `RunStatus`, both card folds and every exhaustive switch stay as they are, and the stored card's `endedAt` is the last moment main saw it alive, so the elapsed is a fact and not `0s`. Terminal cards are stored too, so a relaunch shows the whole conversation's cards.
- **Cards ride in the transcript file, outside `entries`.** `TranscriptRecord` and the renderer's entry union stay as they are; `runs` is an additive optional field, so no version bump and an older file loads with none. Recording after each run event costs one debounced rewrite (at most two a second while prose streams, prose being already coalesced to ten pieces a second); the file grows with each document's text, bounded by `conversation.end`.
- **The two unmeasured stops stay unmeasured.** An interrupt while only text streams, on an idle session, a second one, a stop with background subagents live (`turn-end` then holds the turn open), and an interrupted `Bash` leaving a child are listed in `deferred-work.md`; a stop acknowledged whose `result` never comes leaves the card running, and `close session` is the way out. Build adds no result timeout.
