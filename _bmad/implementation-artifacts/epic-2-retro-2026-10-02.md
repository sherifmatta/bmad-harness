### Cross-story defects (the boundaries no single story saw)

**F1. A main-thread `result` row is taken as the end of the turn the harness sent, and the corpus says that is wrong. Disposition: fix, before Epic 3.**
`endsTurn` clears `inFlight` and announces `session:awaiting-turn` on any main-thread `result` (`src/main/session-bridge.ts:217-224`, `src/main/fold/turn-end.ts:13-18`), re-checked. Story 2.1's own corpus README records the opposite rule: "A session takes turns nobody sent… matching them one to one is wrong" (`fixtures/runs/README.md:21`), re-checked. In `fixtures/runs/fast-path-opus.jsonl` there are 14 main-thread `result` rows against 3 sends, 10 of them after the third send (reported by the verification-gap lens; I counted the 14 rows myself). Consequence chain: `session:awaiting-turn` sets the persona idle (`persona-state.ts:189`), the renderer drains the next queued message (`conversation-state.ts:406-415`), and the decision block can render over a half-streamed list (`transcript.tsx:65-71`). No bridge test replays the corpus; tests use one synthetic `result` per send (`session-bridge.test.ts:353-407`). Story 2.5's AC premise ("a `result` row always belongs to the turn the harness is waiting on", `epics.md:1201`) is itself contradicted by the evidence story 2.1 recorded, so this is also a spec reconciliation. Corroborated by all three review lenses. Prevention: a fact recorded in a corpus README needs an AC or a test in the story that builds on it.

**F2. A turn that never ends, or ends in failure, has no recovery, and the failure is silent. Disposition: fix, before Epic 3.**
`inFlight` clears only on a `result` row, a failed write, or process exit (`session-bridge.ts:217-224, 371-384`), re-checked. No watchdog exists, and `close` is wired in the UI only to the orphan header (`app.tsx`, reported). `endsTurn` deliberately ignores `is_error` and `subtype` (`turn-end.ts:5-12`, re-checked), and `routeFrame` reads only streamed `text_delta`, so a failed activation, an auth failure or an `error_during_execution` result shows nothing and returns the persona to `idle`, not `error` (reported by all three lenses; `error` has no producer in this epic, see F9). The only escape from a wedged session is End session, which clears the transcript. Specs 2.4 and 2.5 deferred this as "no stop control" (`spec-2-4`, `spec-2-5` frontmatter); the Epic 3 stop control is run-scoped and may not cover a chat turn.

**F3. A process that exits mid-turn drops the user's queued messages without a word, and `write()` can report success into a dead pipe. Disposition: fix, with F2.**
`dropQueued` runs from the `session:closed` fold (`conversation-state.ts:196, 391-403`, reported); the `reason` is ignored. `session-process.ts:170-188` swallows stdin errors, so `session/write-failed` is effectively unreachable with a real stream and a user turn can be persisted that nothing received (reported by adversarial, edge-case and verification-gap lenses). Nothing was observed in the behavior check because the stub never died unexpectedly.

**F4. Live order and reloaded order of a typed-mid-turn message differ. Disposition: fix.**
**Observed**: Mary's session was opened by a first message; live order was [user, Hello, reply], after reload [Hello, user, reply] (behavior check item 5). Cause (reported, matches the code shape): the renderer stamps a queued user turn with its own clock and keeps it in place (`use-conversation.ts:245`), while main records it at write time (`session-bridge.ts:392-393`). Already deferred in spec 2.7. `tests/persistence-contract.test.ts:52-111` covers `persona:said` only, so it cannot fail on this.

**F5. A queued message is lost on reload, silently. Disposition: fix (or amend the epic).**
**Observed**: `SLOW queue-then-reload` then `QUEUED-LOST?`; after reload the message was gone from the transcript and never reached stdin (behavior check item 5). The queue lives in renderer memory only (`conversation-state.ts:29-30`), and spec 2.5 says main is unchanged. Epic 2's own AC says a reload loses "nothing" (`epics.md:1264-1266`); spec 2.7 Design Notes admit the exception. The architecture spine says main owns durable state (AD-7) and serialises the queue (spine :148; reported). Needs a decision: persist in main, or announce the loss, or amend the AC.

**F6. Handoff syline: three correctness gaps. Disposition: fix.**
(a) `service.lastOpened` is assigned inside `handoffFor`, which runs after `await reply` (`session-bridge.ts:305-358`), re-checked, so two quick tile activations are attributed in completion order, not click order, and a reversed sysline can be persisted. (b) A sysline is written on every tile change when the transcript is non-empty, including returning to a persona that has said nothing since (`from !== agentId` is the only guard, re-checked), so browsing A→B→A writes two persisted syslines. (c) The `picking up from` list is Write/Edit only (`WRITE_FIELDS`, `route-frame.ts:71`; `written-paths.ts:59-82`; pinned by `written-paths.test.ts:82-95`) and names a path when the tool_use block closes, not when the tool succeeds (`written-paths.ts:71-79`; no `tool_result` is read anywhere in `src`). Bash heredoc and `memlog.py` writes are never named; the spike measured Bash writes in 6 of 7 trials. Also: `lastOpened` and the written-files map are memory-only, so the first switch after a reload or relaunch writes no sysline (`session-bridge.ts:476`; tested as intended in `session-bridge.test.ts`). The epic AC reads "Given a handoff occurs, then a sysline lands" (`epics.md:1318`).

**F7. Transcript load turns every failure into "empty", and the next write replaces the file. Disposition: fix, before Epic 3 adds record kinds or bumps the version.**
`loadTranscript` returns `[]` for a read error, a corrupt file, a wrong `TRANSCRIPT_VERSION`, a foreign `projectPath`, one bad entry (`entries.every(isRecord)`), or a path inside the project (`src/main/sources/persistence/transcript-file.ts:87-108`), re-checked. The file header says it is "left as it lies until the next write replaces it", and `transcript-file.test.ts:120-140` and `projections/transcript.test.ts:148-160` pin the replacement as intended. Story 2.8's AC says the end control is "the only way" a transcript is cleared (`epics.md:1289-1290`); this is a second, silent way. The pin on the single `clear()` caller is a regex over one source shape (`tests/persistence-contract.test.ts:186-198`), which the review log of spec 2.8 conceded `const t = forProject(p); t.clear()` evades.

**F8. `session.open` trusts any pattern-valid id. Disposition: fix.**
The handler checks `isAgentId` only (`session-bridge.ts:343-358`), re-checked; roster membership is held in main (`nameOf`) but not consulted, and `byAgent` is unbounded. Any matching string becomes `claude` with a first stdin turn of `/<id>`, which can invoke any project skill. The main window also carries no navigation guard, `setWindowOpenHandler` or `senderFrame` check (only the document window does, `doc-window.ts:199-200`; reported), and the behavior check saw Electron's "Insecure Content-Security-Policy" console warning (the only console message in the run). Epic 1's item 9 asked for exactly this hardening.

### Behavior defects observed in the running app

**F9. The transcript does not follow new content. Disposition: fix.**
**Observed** (behavior check, unexpected observations): with `scrollTop` at the bottom (2054), a new user turn and reply grew `scrollHeight` to 2768 then 3104 while `scrollTop` stayed at 2054, so the newest turns and the decision block sat below the fold. No scroll-to-newest code exists in `src/renderer` (grep by the check). Spec 2.4 lists "no scroll to newest" among *rejected* review findings. For a product whose job is "a conversation that holds", a conversation that does not follow its newest turn is a defect, and the ACs never mentioned it.

**F10. After a reload, selection resets to the first persona while another persona's turn is still running. Disposition: fix.**
**Observed** (item 5): selection went from Sally (in flight) to Mary; the composer addressed Mary while Sally's turn ran; clicking Sally afterwards wrote no sysline because main's `lastOpened` was already Sally.

**F11. An interrupted persona turn persists as a fragment with no marker. Disposition: fix.**
**Observed** (item 6): after SIGTERM during `SLOW`, relaunch showed the fragment `(bmad-agent-pm`. The whole transcript is also `JSON.stringify`d and rewritten on a 500 ms debounce, and `before-quit` flushes only on a clean quit (reported by adversarial and verification-gap lenses; `session-bridge.test.ts` / `index.test.ts:103-111` cover the clean path).

**F12. Orphan behavior: the composer switches persona silently, and the last-agent case unmounts the close control. Disposition: decide (Sherif + UX), then fix.**
**Observed** (item 10): when Mary was orphaned, current persona silently became John (`message John`, `aria-current` on John) with no sysline; a message intended for the orphan went to John's process. The orphan header shows no working state, so a mid-turn orphan has no visible activity. With all five agents removed the whole shell unmounted (`Preflight` screen), the orphan's close control and End session with it, while 4 stub processes stayed alive; confirmed in code (`app.tsx:124-139`; `install-state.ts:96-100` blocks on *any* preflight entry as well as no agents) and already deferred in spec 2.11. Also: the roster comes only from `_bmad/config.toml`, so renaming a skill directory did not remove the tile.

**F13. Decision block heuristic. Disposition: fix (small) and defer (sample).**
`decision.ts` turns any final numbered or lettered list of two or more lines under any non-option line into a block, with no question check (`src/renderer/ui/chat/decision.ts:80-117`, re-checked); the option text is sent verbatim, so an option beginning `/` is a slash command. Out-of-order or bold-marked lists give no block. Run over about 122 main-thread messages in all six corpus files it found 0 blocks; those are skill runs, so there is no real conversational sample (spec 2.10 frontmatter rates this "medium (unverified)"). **Observed**: the persona turn keeps the raw A/B/C prose and the block repeats it below (item 8).

**F14. Smaller observations from the running app. Disposition: defer.**
After mouse-cancelling a queued message, `document.activeElement` is `body`, not the composer (item 3). Keyboard cancel was not exercised. A polite live region keeps reading `conversation · ended` into the next conversation (item 9). End session ends with one click and no confirmation; this is by design in the epic (lifecycle control) and is recorded here so it is a decision, not an accident.
