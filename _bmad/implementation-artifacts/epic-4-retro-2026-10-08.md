## Findings

### Defects at story boundaries (diff-scope review, behavior check)

**F1 — The room is lost to the window on reload while its process lives on. High. Fix now.** `session-bridge.ts:540-546` builds the snapshot from persona sessions only, so after a window reload `state.room` is empty while main's room is still running. Observed in the built app (behavior 15): the view returns to 1:1; the party view shows the old transcript above the chooser with no header, strip, composer or stop; the process keeps streaming into that read-only thread. *Open the room* then returns the live session without spawning (`session-bridge.ts:196-197`) but the renderer stores the newly chosen cast as the room's cast: a three-person room re-attached with the default five read "5 participants", elapsed restarted, topic gone, summary destination fell back to `<topic>` (review 1; behavior 15). This breaks 4.2's "every chosen portrait stays permanently visible for the life of the room" and 4.5's "stopped: session released" on a reachable path (the project window's View > Reload). The deferral was passed along and never closed: 4.1's triage deferred it to 4.2, 4.3's triage to 4.5, and 4.5's spec has no row for it (spec reconciliation A3; `spec-4-1-choose-who-is-in-the-room.md`, Review Triage Log and Residual risks). No test hydrates a snapshot while main holds a live room (review verification gap 4). [Lesson: a deferral naming a later story must add the item to that story's ACs at the time (Epic 1 item 16, recurring); see P2.]

**F2 — A room send refused as busy is shown as delivered and never reaches the room. High. Fix now.** `use-conversation.ts:192-196` (`transmitToRoom`) swallows `session/busy`; main records the user turn only after a successful write, so the entry exists in the thread and nowhere else (review 2). The same path carries *Write summary*, so a refused summary ask looks asked. `roomSent` also sets the header topic and so the summary filename before delivery. Two use-conversation tests pin "keeps the entry … and says nothing" (review verification gap 3), so the tests agree with the defect. After a reload the line disappears. Related, from the same send path: *stop room* while a send waits in `interruptTurn` makes the renderer show a failure line for the NOT_FOUND it caused, and the user's entry stays in the stopped transcript as if delivered (review 5, `session-bridge.ts:451-459`). [Lesson: a refusal state needs a user-visible outcome in the story that introduces the interrupt.]

**F3 — Room text is dropped or attributed to the wrong persona. Medium-high. Fix now (decision first).** Mechanism, confirmed in source: `foldPieces` emits speech only while a speaker is set (`route-frame.ts:366-376`), a new CLI message clears the speaker (`route-frame.ts:407-411`), and the speaker otherwise persists until the next marker. Consequences, each from a different source:
- *Marked turns are reliable on real data.* Against the one real party session in the user's logs (two rooms, five-agent default cast, `party_mode: session`), `party-speech.ts` attributed 169 of 169 marker-shaped lines, with 0 false negatives, 0 false positives on bold labels, and 0 differences across 1,313 split-delta runs (real-data check; log id `24e16a16`, lines 338-453 and 546-605).
- *Unmarked text is lost.* In the same data, 21.5% of room text (5,604 of about 26,100 characters) never reaches the thread: the skill's welcome and roster list, and the orchestrator's own questions to the user. The product therefore shows a room with a sysline and nothing else until the first persona marker (real-data check; behavior 8; spec reconciliation B4).
- *Orchestrator tails land in the last speaker's turn.* About 11% of attributed text (2,233 of 20,487 characters) is orchestrator prose after the last `---`, rendered as the last persona's words; staging lines such as `*beat*` also attach to the previous speaker (real-data check; behavior 8). This is the opposite of "never attributes words no marker named", the line the 4.6 audit claims to pin.
- *Continuation after a tool call is dropped.* A persona who calls a tool and continues in the next message without repeating the marker has the continuation dropped (review 3; `route-frame.test.ts:744-770` specifies the drop).
- *A persona's own list item becomes another persona's turn.* `MARKER` allows any `\S{1,8} ` prefix (`party-speech.ts:41`) and the accept rule tests the whole roster, not the cast (`route-frame.ts:459-466`): `🏗️ **Winston:** Options:\n- **Mary:** do x` yields a Mary turn, lights Mary, and persists with Mary's `agentId`, including when Mary is not in the cast (`[ran]`, review 4; `route-frame.test.ts:695` enshrines `- **Mary:**` as a marker).
- *A guest outside the cast has a turn and no card.* Mary speaking in a three-person room renders with her portrait, nobody is lit, and the room still reads "3 participants" (behavior 9).
- *The room's reply to the summary ask is dropped,* so nothing tells the user the file landed or the ask was declined (behavior 11).
The skill's wrap-up and "add staging and connective tissue" instructions (`SKILL.md`, "Keep It Feeling Like a Party", "Wrapping Up") make unmarked text normal rather than rare. `party_mode` is `session` in every real log; behavior in `auto`, `subagent` and `agent-team` modes, where a persona's words may sit in subagent frames the product drops by design (`frame.ts:64-71`), has no evidence either way. [Lesson: six stories built on a premise nobody ran; see P3.]

**F4 — "Stop room" is a kill, not an interrupt, and is unguarded. Medium. Defer to a decision.** Observed: process count 1 → 0 within about 100 ms with no interrupt in the stub log, idle or mid-turn (behavior 13). So no wrap-up runs (the skill reads takeaways back, tops up the memlog and offers a keepsake HTML on done, `SKILL.md` "Wrapping Up"), a summary write in flight is cut, and a half-written room file is possible. AD-18/FR84 give *stop* the meaning "interrupt the turn, the session lives"; for the room it means kill, and the room has no interrupt-only control (typing is the only interrupt) (spec reconciliation A2, B5). Also: *Write summary* has no busy guard and the audit test asserts it must not (review 5, verification gap 7), so pressing it twice or mid-turn interrupts the speaker. Typing "we're done" can start the skill's wrap-up and write a second room-owned file the epic never mentions. [Lesson: the epic reused the word *stop* without re-deciding what it means for a session that is not a run.]

**F5 — Old rooms' words and lines stay in every later room's thread, with no boundary. Medium. Fix now.** `party-view.tsx:19-22,82` accepts any `room` entry; `party-view.dom.test.tsx:156` pins "keeps the earlier entries above a new room". Observed: after stop then open again the first room's whole transcript is in the same column, with only a new sysline, and the header counter restarts, so thread length and "turn N" disagree (behavior 14; review 6). 4.1's triage rejected it as a 4.5 matter; 4.5 kept it by design.

**F6 — The Room panel's "context" is every rail row the room did not write, and pushes the destination out of view. Medium. Fix now (decision first).** `room-panel.tsx:35` lists all rail rows not marked `room`; the watcher admits all of `_bmad/` (`watch-artifacts.ts:60-75`) — about 80 paths in the behavior-check project, 196 files in this repo. The panel scrolls and the destination row sits below them (behavior 6), against 4.3's "destination visible without scrolling" and "sized to the Room section's own content". It is not "documents in scope" in any sense the room read (spec reconciliation C). Memlog writes by the skill appear as rail rows and so as "context" too (B5). At 1180px and below the panel is hidden outright (as 4.3 requires), so the destination is shown nowhere at narrow widths although 4.4's AC says it was visible in the Room section before the file was written (behavior 18; review 10).

**F7 — The room thread carries harness lines beyond the two the 4.6 audit counts, including next-step guidance. Low-medium. Fix now.** `sayLine` flags every line of an agentless entry `room: true` (`session-registry.ts:436-441`), so the quiet-timeout line `no output for 120s · the session may be stuck · close it to start over`, the failed-turn line and `session ended · the process exited` render in the party thread. The first is guidance and names "close" where the room's control is *stop room*. The 4.6 static test counts only `room\w+:` keys in `session-voice.ts` (review 7; aggregate §5, confirmed by probe; `session-voice.ts:19-21,36`). Any room turn silent for 120 s, such as a long subagent wait, triggers it. [Lesson: the audit enumerated names, not what renders.]

**F8 — The summary ask and its aftermath are rougher than the story says. Low-medium. Defer to a decision.** The ask is a long, sentence-case, harness-authored paragraph recorded and shown as the user's own turn (`room-summary.ts:9`; behavior 11; spec reconciliation A4), against NFR24's lower case, mono, facts-only register; 4.4's Design Notes accept it. The summary filename slug is a 48-character cut of the first message and can end mid-phrase (`…ship-on-the.md`) or collapse for non-ASCII topics (`Résumé` → `r-sum`, `日本語` → `<topic>`) (behavior 11; review "boundaries checked"). "Topic" is the first non-blank line of the user's first message, so a greeting becomes the topic and the filename (spec reconciliation A6; 4.3 residual risk). The ask may read to the skill as a done-signal and start wrap-up (B6).

**F9 — Cast cards do not wrap at 1000px and a planned layout line is dropped. Low. Fix now or reconcile.** `cast-strip.css` uses `overflow-x:auto` and `flex-wrap: nowrap`; nothing in the 1000px block touches cards. `DESIGN.md:501` says `flex:1 1 44%` and `epic-4-context.md` says cards wrap at ≤1000px while also saying the strip scrolls horizontally. Observed: 5 cards shrink to 184px at 1000px and never wrap; at 420px with three cards they scroll (behavior 18). No story AC names it (spec reconciliation A1).

**F10 — Copy, register and small spec drift. Low.** Capitalised sans harness words in the party view ("Open the room", "Write summary to _bmad/", "Choose who is in the room", panel heading "Room" via CSS uppercase) against NFR24's lower-case mono register (behavior 21). Cast status text is `in the room` where UX-DR21 and the mockup use `present · listening`; three equaliser bars where the mockup has four (`tokens.css:234`); `@name` is plain text where `EXPERIENCE.md:163` specifies addressing semantics and 4.2 forbade `@` logic; `session-voice.ts:30` still reads "Placeholder copy until bmad-ux writes it", the Epic 3 S9 pattern, now four occurrences against three (aggregate §4; spec reconciliation A7-A9). UX-DR21's neutral tags were assigned to Epic 4 and no story builds them; 4.6 reads UX-DR21 as prohibitions only.

**F11 — Accessibility floor gaps on the new surface. Low.** Every user-turn avatar is a tab stop (`span.initials`, `tabindex=0`), so a long thread puts many stops before the chooser or composer; strip cards are not tab stops; `room opened` and `room stopped` come from `harness:said`, which is never announced, so the one polite live region says nothing for the room's lifecycle (behavior 20, 22; review 10). Reduced motion (equaliser to `none`, transitions 0s) and `:focus-visible` rings were confirmed in the real app (behavior 19, 20).

**F12 — Small defects. Low.** A roster name is interpolated raw into the room's first stdin turn (`session-process.ts:101-110`; a name with a newline or parentheses changes the turn, `[ran]` for the string; names come from the user's own install). `spawnSession` falls back to `activationTurn('')`, which is `/`, if neither `firstTurn` nor `agentId` is given. A stream cut with a short token held (`Ok`, `**No`) flushes at the next `message-start` as the old speaker, after the user's interrupting entry (`session-registry.ts:260-264`, `route-frame.ts:407`). The renderer stamps a user entry with the press time while main records the write time, up to 13 s later, so order can change after a reload (review 8-10).

## Process lessons

- **P1 — The "followup review recommended" gate did not hold.** Epic 3 item 47 required a recorded decision before a story with `followup_review_recommended: true` goes to `done`. Stories 4.1 and 4.2 did, with none (above). Their named unverified risks are where F2 and F3 landed: 4.1's "inline-cast turn against the real party skill" and 4.2's "serialised room sends … neither run against a real `claude` party session" (`spec-4-1…:151`, `spec-4-2…:155`).
- **P2 — Deferrals lived in spec prose, not in the register or the next story's ACs.** The reload deferral travelled 4.1 → 4.2 → 4.3 → 4.5 and ended nowhere (F1); `deferred-work.md` has no Epic 4 line; every spec's `deferred: []` is empty while its Review Triage Log carries rejects whose stated reason was "belongs to a later story". Epic 1 item 16 and Epic 3 item 47 both said this; it has now recurred in each of the two epics since.
- **P3 — A whole epic was built on a premise nobody ran.** Six stories, two of them (4.1 first turn, 4.2 attribution) resting on a documented text format and a skill invocation never exercised through the product's argv, and the only real evidence found by this retro lives in the user's private logs, not the repo. Each story's own Residual risks said so. The epic-context note "the orchestration already ships and works" was true of the skill, not of the harness reading it. The fixture-first habit from Epic 2 (a recorded corpus before building) was not applied to party mode.
- **P4 — The 4.6 audit proved prohibited words absent, not good behavior present.** It asserted the banned list (it was clean in the real DOM, behavior 21) yet a guidance line reached the thread (F7) and a harness-authored paragraph shows as the user's turn (F8), because it counted names and checked typed strings. The audit shape that worked in Epic 3 (enumerate what can reach the surface, then assert on that) was copied in name more than in method.
- **P5 — Test-debt carried forward again.** Item 43, "Before Epic 4", did not precede Epic 4; the epic added to the files it named. The behavior-check harness is still scratchpad-only.
- **What worked.** One story per commit with the story number in the subject (attribution by script now works); stories sized so that no story needed a follow-up story (contrast Epic 3's 3.12-3.15); contract counts and layering held throughout; each story's review log recorded reasons for rejections, which is what let this retro trace F1's chain at all.
