## Intent

**Problem:** A rail row (Story 1.11) names a file the user cannot read. Reading it means leaving the window for an editor, or trusting a copy that goes stale the moment a persona writes again.

**Approach:** Make a row an activatable, roving-tabindex control. Activating it asks main to open one read-only document window over the project window. Main watches that single file, reads it, and pushes every change to the window, so the window never asks the disk. The window renders markdown through `markdown-it` (HTML off) and a fail-closed DOMPurify pass, shows the full path and exactly three escapes, closes on `Esc`, and hands focus back to the row that opened it.

## Boundaries & Constraints

**Always:**
- **`doc.open(path)` is a bridge command, not a read** (FR55, AD-13). `src/preload/index.ts` gains `openDoc(path: string): Promise<void>` on channel `doc:open` and `onDocClosed(listener: (path: string) => void): () => void` on channel `doc:closed`: the shell's surface becomes **eight** named methods, no passthrough. `path` is the row's project-relative POSIX path. Main answers `doc:open` only for a window that is a project window (`projectPathForWebContents`); a document window, or an unknown sender, gets `{ ok: false, error: { code: 'doc/no-project', … } }` and nothing opens. The reply envelope is `{ ok: true } | { ok: false, error: HarnessError }`; the preload rejects with the envelope, as `getRail` does.
- **Path validation, two tiers** (NFR8, NFR7). Lexical, in `src/main/sources/project/resolve-document.ts`: a non-string, empty, absolute, backslash-bearing or NUL-bearing path, any `.` or `..` or empty segment, or a first segment other than `_bmad`, is `doc/invalid-path`; no window opens. Real-path: if the target exists, its `realpath` must sit inside `realpath(<root>/_bmad)`; a symlink out is **not** an error reply but a window in state `refused` that reads nothing. A target that does not exist is fine (the row may have just gone): the window opens in state `missing`.
- **One document window per project window.** A second `doc:open` for the same path focuses the open window and opens nothing; a different path replaces it (the old one closes without sending `doc:closed`; the new one's eventual close returns focus to the newest opener). The window is a child of the project window, closes when it closes, and its watcher dies with it (`close`/`closed`).
- **Window mechanics** (UX-DR27, ARCHITECTURE-SPINE `MAIN → DOC: file content on watcher change`). `src/main/windows/doc-window.ts` makes a **frameless, transparent, non-resizable child `BrowserWindow`** sized to the parent's content bounds (`getContentBounds()`), re-fitted on the parent's `move` and `resize`. The page inside paints the scrim and the window card; the OS window is only the stage, which is how the scrim, the 8px radius and the one true shadow exist in a separate OS window. `webPreferences`: `preload` = the doc preload, `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. It is shown on `ready-to-show`, takes the OS title `fullPath` (the `page-title-updated` default is suppressed, as `main-window.ts:75-77`), denies `setWindowOpenHandler` and prevents `will-navigate`/`will-redirect`. `Esc` (`keyDown` of `Escape`, no modifiers) is caught in main by `before-input-event` and closes the window, so it works wherever DOM focus is. Electron and `child_process` calls live only in `src/main/windows/`.
- **Close returns the room** (NFR21). When the user closes the window (Esc, Close, or the OS), main focuses the parent window and sends `doc:closed` with the **project-relative path** to the parent's `webContents` (skipped if it is destroyed). The renderer focuses the row button for that path and makes it the list's tab stop; if the row has since gone, focus falls to the list's current tab stop, and never to `body`.
- **Content comes from the watcher, never from a renderer read** (FR56, AD-13). `src/main/sources/project/watch-document.ts` watches exactly one file with chokidar 4.0.3 (`atomic: true`, `alwaysStat: true`, `ignoreInitial: false`, no `awaitWriteFinish`, no polling), and on its initial `add` and every `change` reads the file in main, bounded and serialised (one read in flight; an event that arrives during a read schedules exactly one more after it, latest wins). `unlink` reports `missing`. The bridge's `doc:get` answers from the projection's **held latest snapshot** after the watcher's first result; it never reads the file itself. `doc:changed` pushes the snapshot whenever it differs from the last pushed (text, state, truncation), not per event. A rapid burst of writes is at most one push per distinct content.
- **Reads are bounded and typed** (NFR8). `DOC_MAX_BYTES = 1_048_576`: at most that many bytes are read and decoded (`TextDecoder('utf-8')`, non-fatal), `truncated: true` when more existed. A NUL byte in the first 8 KiB makes the state `binary` and the text empty. A read error is `unreadable`. **A failed or non-text read never blanks the window**: `missing`, `unreadable` and `binary` keep the last good `text`; before any good read the text is `''`.
- **The snapshot** (`src/shared/document.ts`): `DocState = 'present' | 'missing' | 'refused' | 'unreadable' | 'binary'`, `DocKind = 'markdown' | 'text'`, `DocSnapshot = { revision: number; path: string; fullPath: string; kind: DocKind; state: DocState; text: string; truncated: boolean }`, `DocReply = { ok: true; snapshot: DocSnapshot } | { ok: false; error: HarnessError }`. `path` is project-relative POSIX; `fullPath` is the absolute path, **display data only** — no window opens, reads or reveals by it (reveal and editor act on main's own record for that window). `revision` increases by one per pushed snapshot. `kind` is `markdown` for a `.md`/`.markdown` extension (case-insensitive), else `text` (`fold/document-kind.ts`).
- **The document window's bridge** is its own preload, `src/preload/doc.ts`, exposing `window.docWindow` with exactly five methods: `getDocument(): Promise<DocSnapshot>` (rejects with the envelope), `onDocumentChanged(listener): () => void` (snapshot, never the event), `revealInFinder(): Promise<void>`, `openInEditor(): Promise<void>`, `close(): Promise<void>`. Channels `doc:get`, `doc:changed`, `doc:reveal`, `doc:open-in-editor`, `doc:close`, all exported from both sides and tied by `tests/bridge-contract.test.ts`. **Every handler uses `ipcMain.handle`** (the bridge-contract and startup mocks of `electron` offer no `ipcMain.on`), registering reads and starts nothing, and each acts on the asking window's own entry; an unknown sender is refused. No method takes a path.
- **The escapes** (FR57). *Reveal in Finder* = `shell.showItemInFolder(fullPath)`. *Open in editor* = `execFile('open', ['-t', fullPath])` — the default **text** editor, never `shell.openPath`, which would launch an executable or script. Both are in `src/main/windows/` behind an injectable seam, are refused for a `refused` window, and failures go to stderr as one line, never thrown to the renderer. *Close* and `Esc` close the window. There is **no** fourth control: no refresh, edit, save, copy or open-link affordance (FR59, UX-DR38).
- **Trust boundary in the renderer** (FR58, NFR8, AD-13). The pipeline is `src/renderer/ui/doc/render-markdown.ts`: `markdown-it` 15.0.2 with `html: false`, `linkify: false`, `typographer: false`; image tokens are **dropped and their alt text kept as plain text**; link tokens render as their text with **no `href`** (links are inert: the window navigates nowhere, and opening URLs is not one of the three escapes); then DOMPurify with an explicit allow-list of tags (`h1`–`h6`, `p`, `ul`, `ol`, `li`, `blockquote`, `pre`, `code`, `em`, `strong`, `del`, `hr`, `br`, `table`, `thead`, `tbody`, `tr`, `th`, `td`, `span` — no `a`, since links are already text) and attributes (`class` only), `style`/`img`/`script`/`iframe`/`form` named in `FORBID_TAGS` as well, `FORBID_ATTR` for `style`, `href`, `src`, `srcset` and `on*`. **The sanitiser fails closed**: where DOMPurify is unsupported (`!isSupported` or no `sanitize` function — which is what Node gives, and the suite runs in Node) it returns `''`, never its input. Requirement ids (`FR55`, `NFR8`, `UX-DR27`, `AD-14`, `CAP-7` — pattern `\b(?:UX-DR|NFR|FR|AD|CAP)-?\d+\b`) are wrapped in `<span class="fr">` by a markdown-it core rule over text tokens only, never inside code. The only `dangerouslySetInnerHTML` in the product is in `src/renderer/ui/doc/markdown-body.tsx`, fed only by that pipeline's output. A `text` kind renders as a React text child of a `<pre>`, never through the pipeline.
- **The window renders** (UX-DR27, DESIGN.md `components.document-window` :297-306 and :674-682, mockup `.scrim`/`.win*`/`.md*` :337-372, markup :743-758): a `.doc-scrim` (`--scrim`, `--z-scrim`) and a sibling `.doc-window` (`--z-window`) — `--win-width` × `--win-height`, `--panel` ground, `--rule-width` `--win-line` border, `--radius-window`, `--shadow-window`, top `--win-top`, centred with `margin-inline: auto`, column flex, `overflow: hidden`. **Titlebar** `--win-titlebar` on `--grad-titlebar`, `--line` bottom rule: three 10px `--radius-full` lights (`aria-hidden`, decoration), the **full path** in mono `--fs-ident` `--dim`, one line with ellipsis, then a right-aligned cluster of three ghost buttons in this order — `Reveal in Finder`, `Open in editor`, `Close` — sans, `--panel-2` ground, `--rule-width` `--line` border, `--radius-base`, `--dim`, hover `--text-strong` with a promoted hover border. **Body** `--doc-body-padding` (`26px 34px 40px`), scrolling; the markdown column `max-width: var(--doc-read-max)` centred, `--ink-md`, `--fs-doc-read`, `--lh-read`, with h1 `--fs-h1` `--weight-strong` `--track-h1` over a `--line` bottom rule, h2 `--fs-h2`, h3 `--fs-name` uppercase `--track-md-h3` `--dim`, tables collapsed at `--fs-name` with `--panel-2` uppercase `--fs-ident` headers at `--track-micro`, `.fr` mono `--fs-body-ui` `--accent` nowrap. **Foot** `--win-foot`, `--panel-2` ground, `--line` top rule, mono `--fs-meta` `--faint`: left the state line, right the kind (`markdown · utf-8` / `text · utf-8`, plus `first 1 MiB` when truncated). State lines: `present` → `separate window · read-only preview · reloads on write`; `missing` → `no longer on disk`; `refused` → `outside _bmad/ · not opened`; `unreadable` → `could not be read`; `binary` → `not text · not shown`. The sub-line under the h1 that the mockup draws is fixture data with no source and is **not** drawn.
- **Focus** (NFR21, UX-DR23). On mount the **document region** (`<article tabIndex={-1} aria-label="Document">`, the scrolling body) takes focus, not *Close*. The three buttons are tab-reachable in DOM order and carry the shared ring (no focus rule of their own). The scrim is inert: a click on it does nothing (the escapes are the three and `Esc`).
- **Rows become the roving list** (NFR20, UX-DR18). In `output-row.tsx` a row is `<li>` containing one native `<button type="button" class="output-row-button focus-inset">` holding the existing icon/name/meta; `tabIndex` is `0` for the one tab stop and `-1` for the rest. The tab stop is the row last moved to or opened, else the first in **visual order** (groups in code-unit path order, rows in name order), and a moved-to path the list no longer holds falls through to the first. Arrow travel is `rovingKey` (vertical, clamped) through a new `row-nav.ts` that mirrors `team/tile-nav.ts`; it names no arrow key. The list is one `role`-less `ul`; `Enter` is the native click (Space is too, on a native button — accepted). A click calls `window.harness.openDoc(row.path)`; the rejection of a bad reply is swallowed by the caller (nothing legitimate produces one).
- **The rail's meaning is unchanged.** Rows still carry a watcher-owned disk field and an optional annotation; nothing in this story adds a field, merges them or lets opening a document alter a row. The Outputs half stays monochrome and dense, and `changing` still drives name, text, icon stroke and the pulsing dot.
- **Tokens, promoted** into `tokens.css`'s second `:root`, each commented with its mockup line or DESIGN.md key: `--win-top` (`8vh`, `.win` :341), `--doc-body-padding` (`26px 34px 40px`, `.wbody` :356), `--ghost-border-hover` (`#39414c`, `.ghost-btn:hover` :76), `--ghost-padding` (`4px 10px`, `.ghost-btn` :74), `--win-lights-gap` (`6px`, `.lights` :351), `--win-light-size` (`10px`, :352), `--win-light` (`#3a424e`, :352), plus any further recurring literal the stylesheet needs that `grep` on `tokens.css` does not already find (spend `--radius-base` if that is the 5px `--r`, `--track-h1`, `--track-md-h3`, `--track-micro`, `--weight-strong`, `--doc-read-max`, `--win-*`, `--grad-titlebar`, `--shadow-window`, `--z-scrim`, `--z-window` — all present). No literal colour, dimension, radius or font stack in any new stylesheet; the verbatim first block untouched; motion inventory stays five; **`doc-window.css` is the one stylesheet that spends `--z-scrim` and `--z-window`**.
- **Two bundles, two entries, shared nothing with the shell.** `src/renderer/doc.html` + `src/renderer/ui/doc/**` are the document window's renderer; `electron.vite.config.ts` gains the `doc` input on both `preload` (`src/preload/doc.ts` → `out/preload/doc.js`) and `renderer`. It imports `design/tokens.css`, `page.css`, `focus.css` (the visual contract and the one focus treatment) and `ui/a11y/{announcer,live-region}`; it imports nothing from `ui/shell`, `ui/app.tsx`, `ui/outputs`, `ui/install`, `ui/team` or the shell's preload. It mounts **one polite live region** (the single `aria-live` file is still `a11y/live-region.tsx`) and announces only the transition into `missing`, `unreadable` or `binary`, message = the state line, through the window's own announcer.
- **Layering** (`eslint.config.mjs` LAYER_GRAPH, unchanged): reads and watching in `sources/project/`, pure in `fold/`, the held snapshot in `projections/`, composition in `src/main/doc-bridge.ts` (registered in `index.ts` beside the rail bridge), Electron windows and OS escapes in `windows/`, types in `shared/`, UI in `renderer/ui/`. No new dependency (`markdown-it`, `dompurify`, `chokidar` are already pinned).

**Never:**
- Never a refresh control, edit, save, copy, print, find, zoom, tab or next/previous control in the document window; never a fourth button, a menu, a context menu that edits, or a keyboard shortcut beyond `Esc` (UX-DR38).

## Design Notes

**Why a transparent child window over the parent, not a sized window.** The design calls the document window "a separate OS window over a scrim at z-40, window at z-50, with the one true shadow" (DESIGN.md:676). A sized OS window has nothing to lay a scrim on, clips its own shadow, and cannot show an 8px radius over the desktop. A frameless transparent child that covers the parent's content bounds makes all three true and keeps the mockup's CSS nearly verbatim; it is also what makes "without losing the room" literal — the room is visible behind the scrim and untouched. The cost is bounds-tracking on `move`/`resize`; the OS lights in the titlebar are decoration because the OS draws none.

**Why the scrim is inert.** The mockup closes on a scrim click, but FR57 and EXPERIENCE.md:168 name exactly three escapes and `Esc`. An unlisted fourth escape is a product decision nobody made, and a stray click discarding a half-read document is the worse failure. `Esc` in main (`before-input-event`) rather than in the page means it works wherever focus is, including on the scrim.

**Why main reads and the renderer only receives.** AD-13: the document window has no edge to the filesystem, and FR56 says the reload comes from the watcher. So the window's first snapshot is also the watcher's — `doc:get` returns the projection's held state after the watcher's first read, and every later one is a push. A renderer that could read would have to be trusted with a path, which is the reach the architecture removes. No method on the document window takes a path for the same reason.

**Why the sanitiser fails closed and the markdown layer is split from it.** DOMPurify needs a real `window`; the suite runs in Node, where the library has no `sanitize`. Returning its input there would make every test that touches the pipeline pass through an *unsanitised* path. Splitting `markdownToHtml` (pure, fully testable in Node: html off, images dropped, links inert, ids wrapped) from `sanitizeHtml` (real DOM only) lets the suite prove the first layer exhaustively and the second's contract (allow-list constants, fail-closed) while the real-window behaviour is a manual check. `markdown-it` with `html: false` already escapes raw HTML to text; the allow-list is the second, independent layer FR58 asks for.

**Why links and images are inert.** FR58 forbids images-by-markup, and nothing authorises a link to navigate a read-only preview or to reach `shell.openExternal`; a clickable `https:` inside model-authored text is a phishing surface in a window that looks trusted. Alt text is kept because dropping it silently removes information the author wrote. This can be revisited as an *additive* fifth escape; it cannot be retracted once shipped.

**Why `open -t`.** *Open in editor* must not be able to run a file: `shell.openPath` on a `.command`, `.sh` or an app bundle under `_bmad/` hands it to LaunchServices, which executes it. `open -t` names the default text editor explicitly, and the document being previewed is a file the user already chose to read. `execFile` with an argument vector, never a shell string.

**Why non-markdown files are still openable.** Every row opens (FR55 says "a rail row"), and the install's own files under `_bmad/` are rows (Story 1.11 Design Notes). Plain text in a mono `pre` is honest and cannot inject; refusing would make most rows dead controls.

**Why a failed read keeps the last text.** A persona rewriting a file briefly looks like `missing`, `unreadable` or a torn read; blanking the window on each would be the flash FR52 exists to prevent on the rail. The state line carries the fact; the body is never emptied by an error.

**Containment is per read, not per open.** What a path leads to can change while a window is open, so `readDocument` re-resolves the real path against the real `_bmad/` on every read and opens the resolved path (added in review). A swap to an outside link turns the window `refused` and clears its text; the open-time check in `resolve-document.ts` remains what decides whether a watcher is started at all.

**Left for later, not forgotten.** A `Content-Security-Policy` on `doc.html` (the dev server injects an inline preamble that a strict `script-src` breaks; worth doing once the production path is the tested one). A card-path entry point (Epic 3) and opening from a `doc:*` event. Link handling. Copy-path. A title-bar path that keeps the filename visible when it overflows (the mockup truncates the end). The sub-line under the h1. No DOM environment exists: the focus move, the return of focus, real DOMPurify output, the transparent stage and bounds-following are manual checks, and `useDocument`/`useDocOpen` composition is pinned by pure helpers and text contracts only (the Story 1.2/1.9/1.11 deferral carried forward).

Main validates the path (project-relative `_bmad/…` only), opens one frameless, transparent child window sized to the project window's content bounds (one per project window; the same file focuses it, another file replaces it), and watches that single file with chokidar, reading it in main, bounded to 1 MiB and sniffed for binary. The window is pushed a snapshot only when the content or state changes; it never reads. Its page paints the scrim and the card: a 36px title bar with the full absolute path and exactly three buttons (*Reveal in Finder*, *Open in editor* via `open -t`, *Close*), a focusable document region, and a 28px foot stating the file's state in the harness's microcopy. Markdown goes through `markdown-it` with HTML off, images reduced to their alt text, links made inert, requirement ids wrapped as `.fr`, then an allow-listed DOMPurify pass that fails closed. `Esc` is caught in main and closes the window; on close main focuses the project window and the rail returns focus to the row that opened it. Non-markdown files render as plain mono text; missing, unreadable, binary and refused files state the fact and never blank earlier content. Containment is checked at open and again on every read.
