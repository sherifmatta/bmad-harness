# Epic 7 Context: Work in the conversation, not around it

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Stop making the user work around the conversation. A Board story or epic opens its file; the chat renders the markdown personas write; `/` lists the install's skills; each persona keeps its own live session (a seat) until the user ends it; and a chat can start from a skill with no persona, the skill's name as its speaker, kept in the rail until the user ends it. Every person in the product is a neutral initials disc plus a name; the illustrated portrait is gone and nothing replaces it.

## Stories

- Story 7.1: Open a story or an epic from the Board
- Story 7.2: Read the markdown the personas write, in the chat
- Story 7.3: Find a skill by typing `/`
- Story 7.7: Every person is an initials disc, and the portrait is gone
- Story 7.4: A seat for each persona that stays until you end it
- Story 7.5: Start a chat from a skill, with no persona
- Story 7.6: Nothing this epic promised not to do

## Requirements & Constraints

- Board drill-in: a story's file is the one `spec-<epic>-<story>-*.md` in `implementation-artifacts/`; an epic's is `epic-<n>-context.md` (never a retrospective). Match by number, never by building a name from the sprint key; zero or several matches means no file. Only a card or row with a file is a native button (shared focus ring; no icon, count, path or colour; focus returns on close); the rest are plain text. It opens in the existing document window; the Board writes nothing.
- Chat markdown: a completed persona turn renders through the one existing pipeline (`markdown-it`, HTML off, then DOMPurify) at the chat's own type and measure. Streaming turns stay plain text and render once at the end; an empty render of a non-empty turn falls back to plain text. User turns, syslines, decision blocks, run-card prose and step labels stay plain. Raw HTML, `<style>`, `<script>`, images and `javascript:` links render nothing; links are inert text.
- `/` as the composer's first character opens a list of every installed skill: all, unhidden, unranked, manifest order, name (mono) plus description (`dim`). Typing narrows by case-insensitive prefix; arrows move, `Enter`/`Tab` put `/<name> ` in the composer and send nothing, `Esc` closes. No count, icon, group, accent fill or live-region announcement. `@name` still addresses only a persona. This is the only skill list in the product; whether the New session chat's composer gets it is Story 7.5's call.
- Identity: persona and user are an initials disc (`initialsOf`; one letter for a one-word name) plus a name: 26px on tiles, cast cards, Welcome rows, cast chooser, Agents-panel rows, thread intro, chat turns and seats; 22px in the chat header only; 20px for small references. The disc is `aria-hidden`, no tab stop, neutral for personas (only the user's is tinted); never a persona colour, tint, icon, emoji or image; roster `icon` is never drawn. The Team tile is a 44px row. No portrait module, class or per-person `<svg>` may exist in the renderer.
- Seats: turning to a persona (tile or `@name`) never ends, replaces or re-briefs another seat; no cap; no `handed to <Name>` line for a tile click or `@name` (the `@name` chip stays). A live dot means only "holds context" (no count, no pulse; it pulses only for working); after relaunch no seat is live and the next message starts with no context. The header's `close session` ends one seat, keeps its records, writes one harness line in its own register (`session closed · <Name> starts fresh on the next message`, no persona's face or name), never highlighted or badged. `conversation.end` still ends every seat and is the only thing that clears the transcript.
- Skill-first sessions: a first message `/<name>` naming an installed skill (exact, case-sensitive, not a persona's or the room's) starts one; the speaker is the skill name in mono, never a persona; later plain messages go to the same live session; its lines appear only in its own thread. Ending it (header `close session`) kills the process, removes its own records, writes no line, and lands on the New session chat. After relaunch it is listed as `ended`; a message to it yields one harness line `session ended`, starts nothing, draws no user turn, and the text stays in the composer. Its run card head reads `<skill> run`. In Recent activity its row is the skill name plus `started`/`finished`/`stopped`/`failed` with no code; never a Board column or card, no story owner, not counted in the Agents panel, state strip or Overview. Nothing suggests who to talk to next.
- First-message routing in the New session chat (read in main; the renderer sends only the text): `/bmad-agent-*` turns to that persona's seat; `/bmad-party-mode` goes to the room (text after the name is sent; the empty chat is spent); anything else, text with no `/` and `@name` included, is refused with one harness line `no skill named <word>` (first word as typed, no slash, case kept): no user turn, no persona answers, text stays in the composer, nothing recorded. The line is the command's reply, not a record.
- Negative surface (closing story, each a test): no launcher, palette, recommended, ranked or "next" marker; no counts or badges; no unsanitised markup; one place sets inner HTML; no project writes; no replacement identity device.
- Cross-cutting: tokens only (no literal colours or dimensions); one polite live region per window; reduced motion removes animation; state never by colour or motion alone.

## Technical Decisions

- A session has a kind: persona (`agentId`), room (a cast) or skill-first (a `skill`). An absent `agentId` no longer means the room; send, close, menu dispatch, `conversation.get`, busy-send and harness-line flagging all read the kind. Main keeps one live session per persona; a skill-first session is held by session id with its skill name, no cap. Its records carry a session flag (the room's precedent) and are drawn only in its own thread, never the shared one. The process spawns on the typed message as first turn; the skill is resolved in main and recorded as the run's `skill`.
- Skill list: read once in main from `_bmad/_config/skill-manifest.csv` (`canonicalId,name,description,module,path`, RFC 4180 quoted, so parse, not split), by a reader in `sources/install/` plus a pure fold in `fold/`; carried as an additive `skills` field of the install snapshot. Rows with no `name` skipped; missing or unreadable gives an empty list, no error. The roster still comes only from `[agents.*]`.
- Board files are resolved in main and carried as additive optional `BoardStory.file` / `BoardEpic.file`; the renderer only passes the path to `doc.open`.
- Contract changes are additive; `CONTRACT_VERSION` unchanged: optional `skill` beside `agentId` on `session:opened`/`session:closed`, its listing in `conversation.get`, a session flag on records. No generic `invoke`. The start command carries the whole first message; its reply is opened (`sessionId`), a seat or room to turn to, or refused with the word. Its exact form (a third form of `session.open` or a new command) and whether `session ended` is a record or a reply are Story 7.5's spec. Also open for 7.5: a `bmad-agent-*` row with no `[agents.*]` table; wording when the manifest is missing.
- The New session chat is a renderer surface, not a session: no `sessionId`, process, registry entry, transcript or `userData`; one kept empty chat per window, in memory, no close control; it is what a window opens on, and it ends when its text is sent or the window closes (a reload opens a fresh one). The current persona is optional state: `currentAgent` returns nobody, not the first tile, when none is chosen, and stays derived at render.
- Trust boundary: chat reuses the document window's `renderMarkdown` and its single `MarkdownBody` `innerHTML`; no second pipeline or allow-list.
- Relaunch ends all processes; the CLI starts with no resume flag; resuming a seat is not built.
- Portrait removal (decided 2026-10-15): a removal, not a feature; `Initials` keeps its signature and sizes; no roster, snapshot or contract change. Portrait module, parameter module, stylesheet, tokens and pinned tests go in one change with the matching DESIGN.md keys; the persona-state type moves to the status module.

## UX & Interaction Patterns

- `/` list: above the composer on `panel-2`, 1px `line` border, one focused row with the shared focus ring.
- Team tile and seat: 44px row, 26px disc, name and title beside it, state line with dot below.
- `Skill Session` button (settled): native `<button aria-pressed>` at the right end of the Team sidebar's Sprint board row, drawn as the header's `Stop` (ghost, 5px radius), label only, no icon, count, accent fill or tooltip. Pressed means the empty chat is open (a skill session in view leaves it unpressed). It lists and starts no skill; it is an entry to a chat, not a launcher. Never disabled.
- New session chat: header `New session` with a slash disc at 22px, no status pill, `Stop` or close; empty thread, no placeholder, hint or greeting; focused composer. Clicking a tile, seat, Party or the Board leaves it as is, kept with its half-typed text and refusal lines; the button un-presses and pressing it returns to the same chat. After ending the skill session in view, the window lands here with focus in the composer. On a valid first message the header becomes the skill's name and the button un-presses.
- Skill disc: the same neutral disc holding `/` in mono (never the skill's first letter, since every `bmad-*` would read `B`); 26px in a turn and seat, 22px in the header. Skill-first turn: disc, skill name in mono (`text-strong`), then `HH:MM`; no role or title slot. Skill-first header: disc, skill name, status pill, `Stop` while a turn is in flight and `close session` otherwise; no title or story reference.
- Skill seat: the persona tile's anatomy, not a second component. Name in mono (cut at the row edge), line two `working · <elapsed>` (amber, pulsing), `live` (green dot) or, after relaunch, `ended` (no dot). Group headed `Skill sessions` (existing group-heading treatment) below every persona group, drawn only while one exists, no empty state; start order, no sort or pinning; no control on the row (the header's `close session` is the only end, so a seat out of view is ended by turning to it first); a click turns the chat and marks it current; start time `HH:MM` in `dim` shows only while two seats share a name; arrives in one frame, not announced.
- Persona seat: the existing tile plus the live dot in its own dot vocabulary; no new tile state.
- Mockups illustrate, the spine wins: `skill-session-entry.html`, `new-session-landing.html`; any portrait they draw is superseded.

## Cross-Story Dependencies

- Order: 7.1 and 7.2 in either order, then 7.3, then 7.7 (before 7.4, since seats are drawn on its 44px initials row), then 7.4, 7.5, and 7.6 last. 7.1, 7.2, 7.3 and 7.7 change no session behaviour; 7.4 and 7.5 are one bet, 7.5 depending on 7.4. Stories 7.1 to 7.4 and 7.7 are already built; 7.5 and 7.6 remain.
- 7.7 touches many surfaces and many files import the persona-state type it moves; it adds no skill seat, live dot, `Skill Session` button or `/` disc (7.4 and 7.5 own those).
- 7.5 depends on 7.3 (the skill list the first message is matched against) and 7.4 (seats, the live dot, `close session`). 7.5 is where a window stops always having a current persona.
- 7.6 amends earlier negative-surface audits on purpose: a file card is a control, `/` lists skills, personas have live dots, a chat can have no persona, and no portrait or identity device exists.
- Builds on the document window and sanitisation (Epic 1), session registry, `@name` chip and handoff (Epic 2), the party cast (Epic 4), and the Board with Recent activity and Agents panel (Epic 6). Amends Story 2.9 (composer never names a skill; handoff line), Story 2.8 (ending) and the earlier portrait requirements.
