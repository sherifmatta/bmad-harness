# Epic 3 Context: Run a skill — watch it write, stop it, understand however it ends

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Press a button belonging to the persona you are talking to and watch the document being authored: prose streaming in, the section being written now, the sections still to come, and the run's own reasoning through multi-minute silences, never a spinner. Halt a run at any moment and understand every way it can end without reading logs. This is the product's core and the demonstrable form of its success signal. A thin slice (dispatch, card born, prose streams, `saved`) landed first; a live judgement found the mechanism works but the claim did not yet land (a real run writes many files, and the card followed whichever was touched last), so three follow-up stories land before the rest of the depth.

## Requirements & Constraints

- **Skill buttons:** a row above the composer labelled "<Persona> can ...", each button showing the entry's `description` with a leading `code` chip. A button sends `menu.dispatch(sessionId, code)` and nothing else; main resolves the code and sends `/<skill-name>` or the prompt text verbatim as a turn. An entry with neither `skill` nor `prompt` is a discovery error in the harness's register (names the `code` and what is missing), never a silent no-op or a persona's words. No tooltip or preview derived from a skill name; the user is never shown skill versus prompt. `+N more` expands in place, creates no transcript entry, toggles to `fewer`. Must render at 1 entry and at 10. Buttons are disabled while any turn is in flight in that session; `live` does not disable them; the composer is never disabled. No skills list, launcher or palette exists anywhere.
- **The card is run-scoped:** born on `run:started` in time order, dead on the run's terminal event; a plain chat turn raises none. Head: state dot, mono path, current section, elapsed, stop control. Foot: not-yet-written sections by name, with counts. No denominator or progress bar anywhere, including the rail annotation (`writing · §N <Name>`, never "of M").
- **One document per card:** the card holds a buffer per written path and shows exactly one, its subject, in head path and body. Subject = the file with the most characters written by a `Write` in this run so far (ties to the earlier), changing only when another file's `Write` passes it. Other files the run writes are named in the foot, never in the body or head. A `Write` replaces that path's buffer; an `Edit` of the subject patches it (`old_string` replaced by `new_string`) so the body ends as the whole document; an `Edit` whose `old_string` is absent changes nothing; an `Edit` of another path never touches the body. `saved · just now · N sections` counts the subject's sections only. Real runs write several files (addendum, pre-review copy, PRD) and 32 of 33 writes in one were revision `Edit`s.
- **Pinned while running:** while its run is in flight and its persona is the one viewed, the card is pinned at the top of the chat column (head and body, existing height cap) with the persona's turns scrolling beneath it. On the terminal event it returns to its time-ordered place in one frame, no animation, no thread jump. Non-viewed personas' cards are not pinned (they are collapsed lines). Pinned card is first in the chat column's tab order, takes no focus on pin or unpin, is not a live region. No "jump to card" control, badge or toast.
- **`live` after a run:** a persona's own run must not raise `note`. A watcher change to a file the persona owns, observed while its run is in flight or within the watcher's settle window after the terminal event, is the run's own and raises none; a change outside that window or to a file it does not own still does. Dot reads `work` to `live` for runs writing through `Write`, `Edit` and Bash, verified on a live run as well as the corpus. `live` clears on the next turn or run as today.
- **Never an empty body, never a spinner or a sentence doing a spinner's job.** In a Fast-path run the whole document can land as one write about 8.5 minutes in (a live run reached its first note at ~1m40s, then notes 1 to 5 minutes apart across a 20-minute middle); until prose, the body is the run-note feed from `run:note`. The head keeps path, elapsed and a working stop. A phase word shows only when a feed states it. The foot reads `0 words on disk · <phase> · autosave on`, unsoftened. When prose resumes, accrued notes stay above it in the same scroll container; typeface (prose mono, notes sans) is the only distinction. Subagent activity (`parent_tool_use_id`) is never the persona's voice; `system/task_progress` may render but nothing depends on it.
- **Prose and sections:** prose comes from `input_json_delta` on the write call, never from re-reading disk. Section plan is predicted from the skill's own template under its `assets/` (document sections only; scaffolding headings excluded, emphasis stripped) and refined by the memlog concern-scan entry. Observed headings win, the plan grows, a seen section is never renumbered. A revision `Edit` reads `revising · §N <Name>` and never advances the section counter. `doc:committed` removes every named section from the foot in a single frame.
- **Collapsed card** (persona not current): exactly four fields, persona, last run note's reason (replaces the section name; falls back to it before any note), elapsed, working stop. One line, truncated. Expands on persona switch, click, or `Enter`/`Space`; focus lands on the card container, never the stop control.
- **Stop:** `run.stop(runId)` writes one in-band `control_request` interrupt to that session's stdin. Control reads plain `stop`: no confirmation, no cost copy, no "stopping..." state. The turn's `result` arrives within milliseconds and the card reaches its terminal state on that row. The session survives; the persona explains in its own voice. If the interrupt is not acknowledged (no `control_response`, or non-`success` subtype), fall back to ending the session and say so in the harness's own register (copy for `bmad-ux`). If a stop ever costs more than the turn, the cost goes on the control before it is pressed, never in a modal. The file is left byte-for-byte as written; nothing offers revert or restore.
- **Failure legibility:** terminal state is read from the per-turn `result` row; `is_error: true` means stopped or failed with `subtype` saying which kind; `stop_reason` is never tested and process exit code is never the signal. A `result` ends *a* turn, not necessarily the one sent. A write counts on `tool_result`; exactly one `doc:committed` per tool call carrying its id and sections; on `is_error: true` no sections commit and the rejected call is named. A stopped or failed card names the section reached from the last confirmed write; rail annotation becomes `stopped` with disk state unchanged; the tile goes `error` with no error text. If the session ended with the run, the harness states the outcome in its own register, never a fabricated persona voice. Errors cross the bridge as `{ code, message, detail? }`; raw stderr never reaches the renderer.
- **Rail annotation:** the stream may annotate a row (owner, section in flight, `stopped`, contention) but never create or remove one, assert contents, or move it to `saved`; only the watcher does. An externally edited file shows `changing` with no annotation and reads as complete.
- **Contention:** reported, never prevented or resolved. Annotation names both owners; last writer wins; no lock, revert, patch, restore, merge or undo dialog, and no bridge command for any of them.
- **Unattended completion:** on a terminal event with the window unfocused, exactly one native macOS notification (`John · PRD.md · finished · 15 sections`). Focused window posts nothing. Nothing posts for anything else. No digest or coalescing. Activating it raises the window and scrolls to that run's card, without switching persona or opening anything. Refused or ungranted permission means nothing shown and no second ask. No Dock badge, no sound. Copy states, never guides.
- **Orphans and relaunch:** a run whose agent vanishes from the install keeps streaming; its card stays in time order, collapsed (an orphan is never current), with a working stop found by run and session ids rather than the roster. A stop never closes an orphan; `close session` ends the session, sends the card to a terminal state, keeps the card. If the agent returns, the same session and card resume the ordinary rule. Roster changes mid-run touch nothing else. After relaunch a transcript card renders dead (no ticking, no stop), every persona is `idle`, nothing offers to resume. Accepted limit: the orphan's `close session` is reachable only while the shell is mounted.
- **Performance:** one observed write was 5,795 deltas carrying 69,031 characters. Main coalesces deltas; the card commits accumulated text once per animation frame; no React state update per delta. Verify by replaying a corpus fixture at full rate without dropped frames.
- **Motion and accessibility:** caret blinks with `steps(1)` and is removed, not faded, on finish. Under reduced motion all animation is off but every fact stays legible: elapsed keeps ticking (1s or better) on head and collapsed line, caret static-on, every state string present. Prose is never announced; run notes, lifecycle and commits are announced politely through the single throttled live region (a 15-section commit is one announcement). The card carries `aria-busy` while its run is in flight. A terminal event never moves focus.
- **Negative surface (final story):** no spinner, skeleton or progress bar in any card state; no denominator on head, foot, collapsed line or annotation; no staggered reveal of an atomic commit; no per-character typewriter; no undo, resolve or merge dialog; no Dock badge or sound.
- **Standing rule:** an acceptance criterion that references an external format cites the file it was read from. The `.memlog.md` format has an open kind vocabulary and no per-entry timestamp.
- **Cut line:** contention (3.9) and unattended notifications (3.10) share no file, projection or token with the card state machine and are the only stories that can be dropped if the epic runs long.

## Technical Decisions

- **Replay corpus is the build dependency:** `fold/` interpreters are pure over recorded raw `stream-json` frames in `fixtures/runs/` (Fast-path single write with revision edits and a quiet subagent window, Coaching-path batched write, in-band interrupt, `SIGINT`, reviewer-gate failure via budget cap). Build and test the card against these, not live multi-minute runs. A multi-file `bmad-prd` run (addendum, pre-review copy, PRD, revisions by `Edit`) is re-recorded with `scripts/record-run.mjs` for Story 3.12. Missing or unusable corpus is a blocker. Fixtures store raw frames, so the contract version is forensic only.
- **Contract is already declared in `src/shared/`:** events `run:started`, `run:note`, `doc:section-opened`, `doc:prose`, `doc:committed`, `run:finished`, `run:stopped`, `run:failed`, `rail:changed`; commands `menu.dispatch`, `run.stop`. The renderer sends commands and never parses a raw frame. `runId` keys run-scoped things, `sessionId` session-scoped, personas by `agentId`. Time is epoch ms; elapsed derives from `run:started`. Paths are project-relative POSIX.
- **Routing:** main-thread `text_delta` outside a tool call is `persona:said`; `input_json_delta` on a document write is `doc:prose`; `.memlog.md` writes are `run:note` and never `doc:prose`, so memlog text cannot enter a document buffer or section parser. The tool carrying a document write depends on the model (Write/Edit versus Bash heredocs or Python patches), and the interpreter must handle both; an `Edit` applied by `old_string` fails to patch when a run edits via Bash, and Story 3.12 names the fallback. Per-path buffers supersede the planning spine's single-buffer wording (the architecture doc has not yet been amended).
- **Turns and runs:** one turn in flight per session, sessions concurrent. A run is a turn dispatched from a menu entry; chat and run are both turns into the same session. A session also takes turns nobody sent, and turn-end bookkeeping lives in `src/main/fold/turn-end.ts`, so a `result` row alone is not the end of the sent turn. Queued messages send on `session:awaiting-turn`.
- **Two truth channels never merge:** rail disk state (watcher only: `absent` to `changing` to `saved`) and run annotation (stream only, optional) share no field. The rail projection already accepts an annotation input and is tested against a stub from Epic 1; this epic swaps in the real stream and changes nothing else. Cards are main-held projections re-emitted on reconnect, so a run survives a window reload and no card visual may depend on having seen earlier deltas.
- **Persona state:** `work` persists through quiet subagent phases; `error` is last run failed or stopped (conflated deliberately); a tile aggregates all sessions with its `agentId`. The own-run `note` suppression for 3.13 lives in this projection (`fold/persona-state.ts`).
- **Stop mechanics:** interrupt keeps the session (3-6ms to `result`); `SIGINT` ends it in under 400ms and is reserved for ending a session. The control protocol is undocumented in `claude --help` and a CLI release could change it. Raw logs are forensic only, never the authority for restart display; whether to build the per-session raw log here or amend the requirement is an open ruling.
- **Watcher and layering:** watcher is configured for atomic temp-file rename and ~400ms coalescing; document commits are whole-file writes, so incremental diffing must come from the stream. Every macOS-specific call, including notifications, is confined to `src/main/windows/`. `fold/` has no I/O and no wall clock except injected; projections change only by applying a domain event.
- **Visual contract:** all values come from `design/tokens.css`; a literal colour, dimension, radius or font stack in a component is a defect. The note-blue token is for the `note` dot only; `kind:note` is the neutral tag, and `kind:open` uses the `disagree` tone, never red.
- **Merged scope is load-bearing:** the card's states are one state machine over one projection, and the stop control is a layout field in the head and in the collapsed line. Commit-on-`tool_result` is one function covering happy and failure paths.

## UX & Interaction Patterns

- **Card anatomy:** `card` radius, `panel` body, 1px `line` border. Head on `panel-2` with dot, mono path, status string right-aligned (amber while writing, green when saved), mono elapsed in `faint`, stop control. Body capped at 230px and scrolls, in one of two modes: prose (mono 11.5/1.72, pre-wrap, caret at tail) or run-note feed. Foot on `panel-2` at label size, wrapping, with counts, the named list of sections still to write, and other written files.
- **Card states:** streaming (`writing · §N <Name>`), revising, quiet, stopped or failed (`stopped` plus section reached, body left as-is), finished (`saved · just now · N sections`, dot to `live`, caret removed), dead after relaunch (terminal, no ticking, no stop).
- **Run note:** three-column grid `58px · 74px · 1fr` with tabular-nums mono time, a `kind:` tag (`decision` is the only kind with the accent; `assumption` and `note` neutral; `open` in the disagree tone) and a sans reason with the load-bearing phrase at weight 600. Newest last. Built in Epic 1; here it is mounted and fed live.
- **Skill button:** `panel-2` ground, 1px `line`, 4px radius, leading mono code chip in accent. `+N more` in `faint`.
- **Stop control:** its own tab stop with the shared `:focus-visible` ring. Card expansion moves focus to the card container.
- **Rail annotation:** owner is a session id shown as its `agentId`, else derived from artifact class, else not shown at all (never guessed). The row must read as complete with the annotation absent.
- **Pending copy and design:** the harness's own line when an interrupt falls back to ending the session is still to be written by `bmad-ux`; a pinned-card position in DESIGN.md and the subject/pinned rules in EXPERIENCE.md are pending `bmad-ux` amendments.
