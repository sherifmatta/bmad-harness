# Epic 3 Context: Run a skill — watch it write, stop it, understand however it ends

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Press a button belonging to the persona you are talking to and watch the document being authored: prose streaming in, the section being written now, the sections still to come, and the run's own reasoning through multi-minute silences, never a spinner. Halt a run at any moment, and understand every way it can end without reading logs. This is the product's core and the demonstrable form of its success signal. A thin vertical slice (dispatch, card born, prose streams, `saved`) lands first, and its beat is judged before depth is built.

## Stories

- Story 3.1: Press a button and watch a document write itself
- Story 3.2: The whole menu, and only ever the menu
- Story 3.3: Progress you can read against a plan
- Story 3.4: The card is never empty
- Story 3.5: The run you are not looking at
- Story 3.6: The rail learns who is writing
- Story 3.7: Stop a run, knowing what it costs
- Story 3.8: Understand a run that ended early
- Story 3.9: Two writers, one file, no arbitration
- Story 3.10: Told once, quietly, when you are elsewhere
- Story 3.11: Nothing this epic promised not to do

## Requirements & Constraints

- **Skill buttons:** a row above the composer labelled "<Persona> can ...", each button showing the entry's `description` with a leading `code` chip. A button sends `menu.dispatch(sessionId, code)` and nothing else. Main resolves the code and sends `/<skill-name>` or the prompt text verbatim as a turn. An entry with neither `skill` nor `prompt` is a discovery error in the harness's register (names the `code` and what is missing), never a silent no-op and never a persona's words. No tooltip or preview derived from a skill name, and the user is never shown skill versus prompt. `+N more` expands the row in place, creates no transcript entry, and toggles back to `fewer`. Must render at 1 entry and at 10. Buttons are disabled while any turn is in flight in that session; `live` does not disable them, and the composer is never disabled. No skills list, launcher or palette exists anywhere.
- **The card is run-scoped:** born on `run:started` in time order, dead on the run's terminal event; a plain chat turn raises none. Head: state dot, mono file path, current section, elapsed, stop control. Foot: not-yet-written sections by name, with counts. No denominator or progress bar anywhere, including the rail annotation (head reads `writing · §N <Name>`, never "of M").
- **Never an empty body, never a spinner or a sentence doing a spinner's job.** In a Fast-path run the whole document lands as one write about 8.5 minutes in; until then the body is the run-note feed from `run:note`. The head keeps path, elapsed and a working stop. A phase word shows only when a feed states it. The foot reads `0 words on disk · <phase> · autosave on`, unsoftened. When prose resumes, accrued notes stay above it in the same scroll container; the only distinction is typeface (prose mono, notes sans), with no added container, rule, label or ground. Subagent activity (`parent_tool_use_id`) is never the persona's voice; `system/task_progress` may render but nothing depends on it.
- **Prose and sections:** prose comes from `input_json_delta` on the write call, never from re-reading disk. Section plan is predicted from the skill's own template under its `assets/` (document sections only; scaffolding headings excluded, emphasis stripped) and refined by the run's memlog concern-scan entry. Observed headings win, the plan grows, and a seen section is never renumbered. A revision `Edit` reads `revising · §N <Name>`, patches the buffer, and never advances the section counter (20 of 21 observed writes were revisions). `doc:committed` removes every named section from the foot in a single frame, with no stagger.
- **Collapsed card** (any card whose persona is not current): exactly four fields, persona, last run note's reason (replaces the section name; falls back to the section name before any note), elapsed, working stop. One line, truncated. Expands on persona switch, click, or `Enter`/`Space`; focus lands on the card container, never the stop control.
- **Stop:** `run.stop(runId)` writes one in-band `control_request` interrupt to that session's stdin. The control reads plain `stop`, with no confirmation, no cost copy, and no "stopping..." state. The turn's `result` arrives within milliseconds and the card reaches its terminal state on that row. The session survives and the persona explains in its own voice. If the interrupt is not acknowledged (no `control_response`, or a non-`success` subtype), fall back to ending the session and state that in the harness's own register. The on-screen line is copy for `bmad-ux`. If a stop ever costs more than the turn, the cost goes on the control before it is pressed, never in a modal. The file is left byte-for-byte as written; nothing offers revert or restore.
- **Failure legibility:** terminal state is read from the per-turn `result` row; `is_error: true` means stopped or failed with `subtype` saying which kind; `stop_reason` is never tested and process exit code is never the signal. A `result` row ends *a* turn, not necessarily the one sent. A write counts on `tool_result`; exactly one `doc:committed` per tool call carrying its id and sections; on `is_error: true` no sections commit and the rejected call is named. A stopped or failed card names the section reached from the last confirmed write; the rail annotation becomes `stopped` with disk state unchanged; the tile goes `error` with no error text. If the session ended with the run, the harness states the outcome in its own register and never fabricates a persona voice. Errors cross the bridge as `{ code, message, detail? }`; raw stderr never reaches the renderer.
- **Rail annotation:** the stream may annotate a row (owner, section in flight, `stopped`, contention) but never create or remove one, assert contents, or move it to `saved`; only the watcher does. A row written by an external editor still shows `changing` from watcher activity with no annotation and reads as complete.
- **Contention:** reported, never prevented or resolved. The annotation names both owners; last writer wins; no lock, revert, patch, restore, merge or undo dialog, and no bridge command for any of them.
- **Unattended completion:** on a terminal event with the window unfocused, exactly one native macOS notification (`John · PRD.md · finished · 15 sections`: persona, outcome, file, count). Focused window means nothing is posted. Nothing posts for anything else (commits, notes, rail, queued sends, roster). No digest or coalescing across sessions. Activating it raises the window and scrolls to that run's card, without switching persona or opening anything. A refused or ungranted permission means nothing shown and no second ask. No Dock badge and no sound anywhere. Copy states, never guides.
- **Orphans and relaunch (carried from Epic 2):** a run whose agent vanishes from the install keeps streaming, its card stays in time order, collapsed (an orphan is never current), with a working stop found by run and session ids rather than the roster. A stop never closes an orphan; `close session` ends the session, sends the card to a terminal state, and keeps the card. If the agent returns, the same session and card resume the ordinary full-or-collapsed rule. Roster changes mid-run touch nothing else. After relaunch a transcript card renders dead (no ticking, no stop), every persona is `idle`, nothing offers to resume. Accepted limit: the orphan's `close session` is reachable only while the shell is mounted (at least one agent still resolves).
- **Performance:** one observed write was 5,795 deltas carrying 69,031 characters. Main coalesces deltas; the card commits accumulated text once per animation frame; no React state update per delta. Verify by replaying a corpus fixture at full rate without dropped frames.
- **Motion and accessibility:** caret blinks with `steps(1)` and is removed, not faded, on finish; `work` to `live` on `run:finished` with head `saved · just now · N sections`. Under reduced motion all animation is off but every fact stays legible: the elapsed counter keeps ticking (1s or better) on head and collapsed line, the caret is static-on, every state string is present. Prose is never announced; run notes, run lifecycle and commits are announced politely through the single throttled live region (a 15-section commit is one announcement). The card carries `aria-busy` while its run is in flight. A terminal event never moves focus.
- **Negative surface (final story):** no spinner, skeleton or progress bar in any card state; no denominator on head, foot, collapsed line or annotation; no staggered reveal of an atomic commit; no per-character typewriter; no undo, resolve or merge dialog; no Dock badge or sound.
- **Standing rule:** an acceptance criterion that references an external format cites the file it was read from. The `.memlog.md` format has an open kind vocabulary (13 kinds observed) and no per-entry timestamp.
- **Cut line:** if the epic runs long, contention (3.9) and unattended notifications (3.10) share no file, projection or token with the card state machine and are the only stories that can be dropped.

## Technical Decisions

- **Replay corpus is the build dependency:** `fold/` interpreters are pure over recorded raw `stream-json` frames in `fixtures/runs/` (Fast-path single write with revision edits and a quiet subagent window, Coaching-path batched write, in-band interrupt, `SIGINT`, reviewer-gate failure induced by a budget cap). Build and test the card against these rather than live multi-minute runs. A missing or unusable corpus is a blocker. Fixtures store raw frames, so the contract version is forensic only.
- **Contract is already declared in `src/shared/`:** events `run:started`, `run:note`, `doc:section-opened`, `doc:prose`, `doc:committed`, `run:finished`, `run:stopped`, `run:failed`, `rail:changed`; commands `menu.dispatch`, `run.stop`. The renderer sends commands and never parses a raw frame. Identity: `runId` keys run-scoped things, `sessionId` session-scoped things, personas by `agentId`. Time is epoch ms in events, and elapsed derives from `run:started`. Paths are project-relative POSIX.
- **Routing:** main-thread `text_delta` outside a tool call is `persona:said`; `input_json_delta` on a document write is `doc:prose`; `.memlog.md` writes are `run:note` and never `doc:prose`, so memlog text cannot enter the document buffer or section parser. The tool carrying a document write depends on the model (Write/Edit versus Bash heredocs), and the interpreter must handle both. A `Write` replaces the buffer and may open sections; an `Edit` patches it as a revision.
- **Turns and runs:** one turn in flight per session, sessions concurrent. A run is a turn dispatched from a menu entry; chat and run are both turns into the same session. A session also takes turns nobody sent, and turn-end bookkeeping lives in `src/main/fold/turn-end.ts`, so a `result` row is not by itself the end of the sent turn. Queued messages send on `session:awaiting-turn`.
- **Two truth channels never merge:** rail disk state (watcher only: `absent` to `changing` to `saved`) and run annotation (stream only, optional) are independent fields with no shared field. The rail projection already accepts an annotation input and is tested against a stub from Epic 1; this epic swaps in the real stream and changes nothing else. Cards are main-held projections re-emitted on reconnect, so a run survives a window reload and no card visual may depend on having seen earlier deltas.
- **Persona state:** `work` persists through quiet subagent phases; `error` is last run failed or stopped (the two are conflated deliberately); a tile aggregates all sessions with its `agentId`.
- **Stop mechanics settled in Epic 1:** interrupt keeps the session (3-6ms to `result`, n=4); `SIGINT` ends it in under 400ms and is reserved for ending a session. The control protocol is undocumented in `claude --help` and a CLI release could change it. Raw logs are forensic only, never the authority for restart display; whether to build the per-session raw log here or amend the requirement is an open ruling.
- **Watcher and layering:** watcher is configured for atomic temp-file rename and ~400ms coalescing; document commits are whole-file writes, so incremental diffing must come from the stream. Every macOS-specific call, including notifications, is confined to `src/main/windows/`. `fold/` has no I/O and no wall clock except injected; projections change only by applying a domain event.
- **Visual contract:** all values come from `design/tokens.css`; a literal colour, dimension, radius or font stack in a component is a defect. The note-blue token is for the `note` dot only; `kind:note` is the neutral tag, and `kind:open` uses the `disagree` tone, never red.
- **Merged scope is load-bearing:** the card's six states are one state machine over one projection, and the stop control is a layout field in the head and in the collapsed line. FR88's commit-on-`tool_result` is one function covering happy and failure paths.

## UX & Interaction Patterns

- **Card anatomy:** `card` radius, `panel` body, 1px `line` border. Head on `panel-2` with dot, mono path, status string right-aligned (amber while writing, green when saved), mono elapsed in `faint`, stop control. Body is capped at 230px and scrolls, in one of two modes: prose (mono 11.5/1.72, pre-wrap, caret at tail) or run-note feed. Foot on `panel-2` at label size, wrapping, with counts and the named list of sections still to write.
- **Card states:** streaming (`writing · §N <Name>`), revising, quiet, stopped or failed (`stopped` plus section reached, body left as-is), finished (`saved · just now · N sections`, dot to `live`, caret removed), dead after relaunch (terminal, no ticking, no stop).
- **Run note:** a three-column grid `58px · 74px · 1fr` with a tabular-nums mono time, a `kind:` tag (`decision` is the only kind with the accent; `assumption` and `note` neutral; `open` in the disagree tone) and a sans reason with the load-bearing phrase at weight 600. Entries stack newest last. This component is built in Epic 1; here it is mounted and fed live.
- **Skill button:** `panel-2` ground, 1px `line`, 4px radius, leading mono code chip in accent. `+N more` renders in `faint`.
- **Stop control:** its own tab stop with the shared `:focus-visible` ring. Card expansion moves focus to the card container.
- **Rail annotation:** owner is a session id shown as its `agentId`, else derived from artifact class, else not shown at all (never guessed). The row must read as complete with the annotation absent.
- **Interrupted-run wording:** the harness's own line when an interrupt falls back to ending the session is copy still to be written by `bmad-ux`.

## Cross-Story Dependencies

- **3.1 lands first and gates the rest.** It is the thin slice of the beat and a recorded judgement on whether it lands is required before 3.2 onward. It depends on Epic 2's contract, sessions and corpus, and on Epic 1's run-note feed.
- **3.2 completes the button row 3.1 starts.** 3.3 and 3.4 build the card's progress and dead-air behaviour on 3.1's card and the Epic 1 feed. 3.5 depends on the card head and stop field those stories set out.
- **3.6 depends on Epic 1's rail annotation slot and stub source** and on the owner and section data the card projection produces.
- **3.7 and 3.8 share the terminal-state path.** 3.7 depends on 3.1's card and 3.5's collapsed line. It also carries clauses from Epic 2: the orphan card and stop controls from Story 2.11, and the dead-card-after-relaunch clause from Story 2.7. 3.8 needs the `doc:committed` and `result` handling plus the interrupt, `SIGINT` and reviewer-gate fixtures.
- **3.9 and 3.10 depend on 3.6's annotation and on terminal events.** They are the descope boundary.
- **3.11 runs last** and reviews all of this epic's surfaces.
- **The turn-queueing open item inherited from Epic 2 resolves here**, against a real run. Whether a queued message reads as honest during a twelve-minute run could not be answered in Epic 2 because it had no runs.
- **Epic 4 (party mode) is independent of this epic.**
