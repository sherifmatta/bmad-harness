### B. Lens findings (`bmad-review` on the full diff)

Weighted toward the seams between stories, as asked. The adversarial lens must report at least ten and returned eighteen; edge-case-hunter returned seventeen (several overlap, which is signal); verification-gap returned four. Overlap is noted rather than deduplicated.

*Confirmed against source by the retro author:*

1. **Packaged-app PATH (overlap: adversarial, edge-case, verification-gap).** `claude` and `uv` are spawned with `process.env` unchanged (`tools.ts:83-85`, `resolvers.ts:102`). A packaged app launched from Finder gets launchd's minimal PATH, so a correct install reports "claude · not on path" or "uv · not found" and the room never opens. `epics`/context scope v1 as "from dev or a local unsigned package", so packaged builds are in scope. The behavior check reproduced the message with `PATH=/usr/bin:/bin`; the Finder-launch behavior itself is standard macOS and was *not* run (packaged build not exercised). Every test injects the runner. *Fix now.*
2. **Preflight verdict is cached for the window's life** (`projections/install.ts:119-154`, "keep the answer for the window's life"). A user who follows the remedy ("install uv", sign in to claude) stays blocked until they close and reopen the window; a transient `check-failed` blocks the same way. The install watcher only watches config files. Related and already deferred in `spec-1-8`: an install created while the window sits on the blocked screen is not noticed. The remedy text promises recovery the harness cannot deliver. *Fix now.*
3. **Sanitiser allow-list does not match what markdown-it emits.** `ALLOWED_TAGS` has `del` but not `s`; `ALLOWED_ATTR` is `['class']` only (`render-markdown.ts:40-60`). Running markdown-it on `~~gone~~` gives `<s>gone</s>`, and a list resumed after a code block gives `<ol start="2">` — both stripped by DOMPurify (reproduced). In the shipped document window strikethrough renders plain and resumed numbered lists restart at 1. No test sees it: DOMPurify reports unsupported under Node and fails closed (`render-markdown.ts:203-208`), so the real sanitiser has never run in any test (`render-markdown.test.ts:185-216`, `doc-app.test.tsx:78-85` assert an empty body). Related: `markdown-it`'s fence rule emits `class="language-<info>"` and `class` is allowed, so an author can place `language-*` classes. *Fix now (allow-list), root cause is item below.*
4. **No DOM test environment, never decided.** `vitest.config.ts:7` is `environment: 'node'`; no `jsdom`/`happy-dom` is installed. The register assigned the decision to Story 1.9 (`deferred-work.md`, third entry); 1.9 declined (`spec-1-9:51,175`) and 1.11 carried it forward. As a result no test mounts a component, fires an event, focuses an element or resolves a media query; renderer claims are static markup, hook-stubbed function calls, or CSS read as text. The hooks `useRail`/`useInstall`/`useDocument`, `LiveRegion`'s drain interval and `useNow` are unobserved (`use-rail.ts:27-31`, `use-install.ts:33-37`); a regression that replaced `acceptRail(current, incoming)` with `setSnapshot(incoming)` would pass every test. **This is the root cause of the largest group of unverified claims across 1.9–1.14.** *Fix now: decide before Epic 2 builds the composer and turn on it.*
5. **`icon` and `description` are required by the roster validator and one bad entry rejects the whole roster** (`schema.ts:48-49,84-92`). `icon` crosses the bridge and no renderer reads it; one custom agent omitting a cosmetic field makes the entire team vanish behind `resolver/unexpected-shape`. *Defer.*
6. **Integer-like agent ids sort first.** `SAFE_AGENT_ID` allows ids starting with a digit (`schema.ts:29`) and roster order is `Object.keys` of parsed JSON (`schema.ts:71-77`), which JS orders numerically first; an id such as `7` would become the topmost tile and default persona, against the "config order, no sort" contract. *Defer.*
7. **A failed renderer load loops forever.** `did-fail-load` calls `window.destroy()` (`main-window.ts:78-93`), which fires `window-all-closed`, which reopens the project chooser (`main/index.ts:95-97`); the failure goes only to `console.error`. A missing `out/renderer` or dead dev server gives chooser → window → destroy → chooser. Read from the code path, not executed. *Defer.*

*Reported by the lenses, plausible, not independently re-run:*

8. The document stage covers only the parent's content bounds and is non-modal; nothing handles the parent regaining focus, so keyboard focus can sit in the occluded project window where Enter on a hidden row replaces the open document (`doc-window.ts:132-147,169-182`). Esc works only while the doc window has OS focus (the behavior check confirmed Esc via a synthetic key event only).
9. A missing file under an ancestor directory symlinked out of `_bmad/` opens as `missing` rather than `refused`, and "Reveal in Finder" then runs on a path outside `_bmad/` (`resolve-document.ts:70-79`, `doc-bridge.ts:104-107`, `macos-escapes.ts:35-47`). Escape actions trust cached snapshot state and do not re-check containment (`macos-escapes.ts:50-66`). The 1.12 triage found the open-time-only containment check and patched per-read containment; the escape path was not covered.
10. `openDocument` swallows every `doc:open` rejection (`use-doc-open.ts:18-23`); a file with a backslash in its name is a valid rail row that `documentSegments` refuses (`resolve-document.ts:33`), so the row is a dead control with no message — against FR91 ("every failure crossing the bridge renders a line").
11. Watchers rooted at paths that do not exist yet never see creation of the root (`watch-install.ts:99-104`, `watch-artifacts.ts:54-59`, `watch-document.ts:203-207`); the edge-case lens reports it verified against chokidar 4.0.3. Watcher `error` events are swallowed or only logged (`watch-install.ts:113`, `rail-bridge.ts:79-80`, `watch-document.ts:220-224`): rows and text freeze while the foot still says "reloads on write".

A valid-but-empty resolver answer (config momentarily truncated, `{}`) replaces a last-good roster with an empty one and flips the room to blocked (`schema.ts:61-63`, `projections/install.ts:220,245-246`); a missing resolver script also yields `agents: []` with no error (`resolvers.ts:132-134`).

A render-process crash leaves the transparent stage window over the parent (`doc-window.ts:82-101`).
15. Worst-case "ready" latency is roughly 2×15s for uv, then 15s for the roster, then 15s for the menus, with a blank window throughout (no spinner by design).
16. `initialsOf` slices by UTF-16 unit (`initials.tsx:41-46`); an astral first character yields a lone surrogate. UTF-8 truncation at `DOC_MAX_BYTES` can end a document in U+FFFD (`watch-document.ts:99-112`). A zero-byte file is "not yet written" forever in the rail but `present` in the document window (`rail-rows.ts:54-56`).

### C. Verification quality (what the green suite does and does not mean)

The 1398 passing tests are real, and the gates are clean, but the shape matters for Epic 2. Of Story 1.14's criteria, audio, legend-in-source, reduced motion, the faint-tier rule, ⌘K, and the menu checks rest **solely** on source-text sweeps (`tests/negative-surface.test.ts`, 632 lines). The rendered counterpart (`negative-surface.test.tsx`, 217 lines) uses `renderToStaticMarkup`. Judgement calls the story made without asking: the Outputs rail lists `config.toml`, `config.user.toml` and `custom/*.toml` as clickable rows and the test pins "a file named config.toml is data" (`negative-surface.test.tsx:139-147`), while the AC says no configuration file path in "any user-facing copy"; `.rail-group` (the directory heading, `--meta`, below `faint`) is the only thing telling two same-named files apart (`outputs.tsx:118-119`, `output-row.tsx:90`) and `.chat-head-sub` (faint) is the only place `description` renders.

*Disposition: the verification shape is the DOM-environment decision (item 4); the two judgement calls are action item 14.*

## DOM test environment recommendation

**Recommend jsdom 30.1.1, opted into per test file with `// @vitest-environment jsdom`, leaving `environment: 'node'` as the default.** Status: a recommendation; nothing is installed in the repository.

*Evidence.* I ran the same three probes under each candidate in an isolated scratch project (outside the repo) with the repo's own pinned Vitest 5.0.1, Vite 7.3.6, React 19.3.0, markdown-it 15.0.2 and DOMPurify 3.4.16, on Node 24.19.0:

| Probe | jsdom 30.1.1 | happy-dom 20.14.5 |
|---|---|---|
| DOMPurify `isSupported` | true | true |
| Sanitising real markdown-it output (`1. a`, fenced code, `2. b`, `~~gone~~`, `<script>`, `<img onerror>`) | correct: both `<ol>` blocks kept, `<s>` and `start="2"` kept with the Epic 1 allow-list fix, script and img gone | **wrong**: the first list lost its `<ol>` wrapper (output began `<li>a</li>`) |
| React 19 mount, `act`, keydown and click handlers, `focus()` / `document.activeElement` | pass | pass |
| `document.getAnimations` | absent | absent |
| `window.matchMedia` | absent (stub in a setup file if needed) | present |
| Stylesheet parsed, `getComputedStyle` after a rule | works (`rgb(255, 0, 0)`) | works (`red`) |

The deciding row is the sanitiser: the first thing Epic 1 left unobserved is DOMPurify against the document window's real markdown, and happy-dom changed that output on the very path the test is for. A test environment that alters the result under test is worse than none. jsdom is also the environment DOMPurify documents.

*Why per-file opt-in.* Everything under `src/main/**`, the fold and the source-text tests (`tests/*.test.ts`) have no use for a DOM and run in plain Node today (68 files, about 15s). Keeping `node` as the default means none of them changes. Only the files that mount a component or run the sanitiser opt in.

*Costs and constraints.*
- One new dev dependency outside the NFR11 set. NFR11 pins the *application* stack; `DEPENDENCIES.md` already has an "Additions this project chose" table for toolchain packages that may move on their own, which is where it belongs. Vitest 5.0.1 lists `jsdom` as an optional peer of `*`, so no peer conflict. It is not in `scripts/check-pins.mjs`'s `PINS`, so `check-pins` is unaffected (the husky precedent). Pin it exactly (`.npmrc` has `save-exact=true`).
- jsdom 30 declares `node: ^22.22.2 || ^24.15.0 || >=26.0.0`; `package.json` says `>=24.0.0`. Tighten `engines` to `^24.15.0` (this machine runs 24.19.0; Electron 44 bundles 24.18.1).
- No test library is needed. The probe used plain `react-dom/client` with `act`, which is the same device `outputs-focus.test.tsx` already uses; add `@testing-library/react` only if hook tests get verbose.

*What no DOM environment will give you* (both candidates lack it, so it is not a reason to prefer either): real layout (breakpoints, 56px tiles, truncation), media-query evaluation (reduced motion), `:focus-visible` heuristics, hover, and real Electron behavior (Esc, focus return across windows, the application menu). Those stay manual or need an Electron-level smoke. The retro's own behavior check (launch the built app, drive it over the DevTools protocol, assert on the DOM and a screenshot) worked and could become that smoke as a separate item (`npm run smoke`); it is not in the action list yet.

*Suggested first uses, in order:* run the real sanitiser on the document window's markdown (closes B3), then `useRail`/`useInstall`/`useDocument` and `LiveRegion`/`useNow` (closes the largest unverified group in B4), then migrate the negative-surface checks that are currently regexes over CSS where a rendered check is possible.
